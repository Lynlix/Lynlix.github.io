VSCode+MinGW+CMake配置OpenGL环境（glad+glfw库）

一、配置VSCode

VSCode作为一个编辑器来说其实跟记事本没什么两样，但奈何内置的扩展插件实在是太好用了。少了VSCode并不会对代码编译结果有任何的影响，但是没有代码补全却会对代码体验带来灾难性的打击——很难想象以前没有这些工具时的大佬是怎么写下去代码的……

1.官网下载VSCode安装包并安装

  • Visual Studio Code - The open source AI code editor | Your home for multi-agent development

2.安装扩展插件

  • 打开刚刚安装好的VSCode

  • C/C++扩展

  • CMake Tools扩展

二、下载安装MinGW

LearnOpenGL教程里直接使用了VS 2019 IDE，配置起来也很方便，但没有提及MinGW编译OpenGL相关库的详细方法。所以这里选择MinGW作为编译器，以提供另一种选择，后续还要用到MinGW+CMake编译、链接GLFW库。

1.下载MinGW-w64压缩包

  • 推荐从 WinLibs 下载：https://winlibs.com/

  • 选择“UCRT runtime”下的任意版本下载（如：GCC-16.1.0-win64）

  • 下载完后得到相应格式的压缩包（.zip 或 .7z）

2.安装MinGW

  • 然后当然是要解压啦~解压完里面会有个mingw64文件夹

  • 把mingw64文件夹移动到自己喜欢安装的位置即可（这里是放在了D:\）

3.添加环境变量

  • 把mingw64下的bin文件夹路径复制下来（我这边是D:\mingw64\bin）

  • 任务栏搜索“环境变量”然后打开

  • 点击“环境变量”

  • 把之前复制的 D:\mingw64\bin 添加到系统的 PATH 环境变量中

4.验证

  • win+R输入cmd，打开终端，输入

  • 显示对应版本信息即表示安装成功

三、配置CMake

1.下载安装包

  • 访问 CMake 官网：https://cmake.org/download/

    在“Source distributions”部分，直接下载并解压Windows版本的zip即可

  • 如果CMake官网进不去的话，也可以访问Github下载对应的压缩包：https://github.com/Kitware/CMake/releases

    或者直接clone也可以：

  • 如果Github也进不去的话，还可以前往Gitee下载

2.设置环境变量

  • 把CMake压缩包解压到自己想安装的位置（如：D:\cmake）

  • 打开cmake文件夹，复制bin文件夹的路径（如：D:\cmake\bin）

  • 任务栏搜索“环境变量”，打开后找到系统变量Path

  • 依照之前的步骤，把复制过的bin文件夹路径加入到Path确定即可

3.验证

  • win+R输入cmd，打开终端，输入

  • 显示对应版本信息即表示安装成功

四、配置OpenGL

1.下载并编译GLFW库

GLFW是一个开源跨平台库，主要用于窗口创建管理、处理键盘鼠标输入和渲染OpenGL上下文。需要注意的是，GLFW本身并不提供任何GUI控件，只负责提供相关平台的API。

  • 官网获取：Download | GLFW

  • 选择下载源代码包（Source package），从源代码编译库可以保证生成的库完全适合本地的操作系统和CPU。

  • 由于Source package也是从Github下载的，所以有可能会下载失败。推荐下载dev-sidecar，用于快速访问Github。

  • 下载完后解压缩，可以看到glfw文件夹里有CMakeLists.txt

  • 现在开始使用傻瓜版CMake，只需要点点点就能完成构建！找到之前安装好的cmake\bin下双击运行cmake-gui.exe

  • 然后创建一个build文件夹（随便放哪都行）用于CMake构建完的文件

    如果想要构建动态库，可以把BUILD_SHARED_LIBS也勾上。我们这里只需要静态库文件足以，所以就不勾了

  • 然后点击 Configur 进行配置，再点击Generate生成（之后可以在build目录找到生成的Makefile文件）

  • 这时候就要用到MinGW了！在build目录下打开终端，执行以下命令进行编译。

    编译要花点时间，warning不用管

  • 完成编译后打开build\src，成功的话会在该目录下生成libglfw3.a

  • 至此GLFW库编译完成

2.下载并配置GLAD

由于OpenGL只是一个标准/规范，具体的实现完全由不同的驱动开发商针对特定显卡各自独立实现，导致OpenGL的驱动版本众多，多数函数位置都无法在编译时确定下来，需要在运行时查询。于是就需要有GLAD这样的库就负责提供运行时查询的功能。

LearnOpenGL教程中关于GLAD的下载配置流程已经非常详细了，具体如下：

  • GLAD在线配置：http://glad.dav1d.de/

  • 语言(Language)设置为C/C++

  • API选项中，选择3.3以上的OpenGL(gl)版本

  • 模式(Profile)设置为Core

  • 保证选中了生成加载器(Generate a loader)选项

  • 都选择完之后，点击生成(Generate)按钮来生成库文件

  • 最后点击glad.zip下载到本地并解压即可

五、本地化第三方库管理

实际上到此为止OpenGL的相关运行环境已经配置完了，可这样还是太麻烦了，每次写一个新项目都要把第三方库的目录结构整理一遍，然后还要再仔细对照着写一遍CMakeLists.txt！

有没有更轻松，更简便点的方式呢？

有的，有的！那就是vcpkg

用vcpkg包管理器当然也是个不错的选择，但是既然都已经用MinGW把glfw手动编译完了，那干脆想些不依靠vcpkg的法子。

（vcpkg会自动完成第三方库的下载、编译功能，理论上讲非常方便……理论上是这样的，但是vcpkg的第三方库下载源来自Github，经常会出现下载失败的问题。还有就是，vcpkg自身默认的编译器是MSVC而非MinGW。尽管以上两个问题也都有各自的解决方案，但那就又要折腾好半天了……）

言归正传，CMake是个非常强大的构建工具，我们完全可以将编译好的第三方库存储在本地的某个固定目录下，并将这个第三方库路径设置为系统变量。这样CMake可以通过CMakeLists.txt，从系统变量自动读取到第三方库的本地存储路径，也就不需要频繁的复制一堆第三方库文件新建项目了。

1.选择本地化第三方库存储路径

随便选哪里都可以，唯一要注意的是这个路径一定要固定，选好后尽量不要再做改动，否则搬来搬去再改会很麻烦，那就没有意义了。

  • 比如，选择F:\Dev\C++作为第三方库存储路径

  • 然后把之前的package文件夹直接移动过来即可（F:\Dev\C++\package）

2.新建系统环境变量

首先要先自定义一个变量名，可以选择在用户变量栏新建，也可以在系统变量栏新建，没啥太大讲究。这个变量名后面修改CMakeLists.txt会用到，建议先跟我这里设置一样的，等走完流程后再回来根据需求自行定义。

  • 变量名：CPP_PACKAGE_ROOT

  • 变量值：F:/Dev/C++/package（这里注意路径分隔符要换成反斜杠’/‘或者双斜杠’//‘！否则cmake会把单斜杠’/‘自动注释掉）

  • 记得新建完环境变量一路确定，否则不会保存

  • 依旧左下角点击“生成”，VSCode会根据CMakeLists.txt的内容自动生成build文件夹与exe可执行文件，并在终端输出信息

  • 点击左下角“运行”按钮，结果正常运行则验证环境配置成功

这样就通过CMakeLists.txt成功完成了本地化第三方库的配置，后续如果想根据个人喜好自定义更改，则修改CMakeLists.txt对应部分，保存后重新build即可
