一、Hexo环境配置

  • 项目仓库：用于存放hexo项目源码、主题配置、文章图片等
  • 部署仓库：用于暂存hexo一键生成的静态网页文件（html、css、js）

二、创建本地Hexo博客

1.新建项目

  • 选择一个合适的路径，在该目录下空白处单击鼠标右键，选择“Open Git Bash Here”。

  • 自定义一个<项目名>用于初始化，这里将<项目名>命名为。然后在已打开的Git Bash中执行指令： hexo init <项目名>

  • 完成后会在目录下刷新出一个Hexo项目文件夹，表示项目创建成功了。

2.安装依赖

  • Git Bash执行 cd <项目名>进入该目录，然后执行 npm install安装项目依赖：

  • 本地预览验证： 执行 hexo server

  • 浏览器打开 http://localhost:4000，能看到默认的 Hexo 博客页面。按 Ctrl+C 停止服务器。

三、创建GitHub仓库

之前创建成功的网站只是在本地运行，如果想要将其由本地部署到GitHub上，需要在GitHub上分别创建好项目仓库、部署仓库，之后再将本地项目同步至Github的项目仓库，并使其触发Actions自动部署网站。

  • 首先，注册一个GitHub账户，记得起个好听点的用户名，因为后续会将博客部署到<用户名>.github.io的网站上。
  • 如果GitHub访问失败的话，推荐自行安装 dev-sidecar代理用于加速访问。

1.配置SSH密钥

新注册GitHub的账户需要生成一对SSH密钥，并将公钥添加至GitHub账户中，用于后续连接GitHub。

  • 打开Git Bash，执行以下指令生成SSH密钥：

    这里的 GitHub邮箱@example.com要填写与GitHub账户绑定的邮箱，执行完后提示 Enter file in which to save the key时直接按回车（使用默认路径 C:\Users\用户名\.ssh\id_ed25519）。提示输入 passphrase 时，可以直接按 回车 不设置密码（用于自动化更方便），也可以设置一个密码（每次使用需要输入）。

  • 然后直接去C:\Users\用户名\.ssh目录下找生成的密钥

  • 打开id_ed25519.pub文件，全部选中复制公钥

  • 登录 GitHub → 右上角头像 → Settings → 左侧菜单 SSH and GPG keys → New SSH key。

    • Title 随意填，比如 “Windows11 PC”。
    • Key 粘贴刚才复制的公钥内容。
    • 点击 Add SSH key。

  • 验证SSH连接：ssh -T git@github.com

2.创建部署仓库（公开）

部署仓库（公开）：用于暂存hexo一键生成的静态网页文件（html、css、js），仓库名称必须严格命名为 <用户名>.github.io。

  • 登录 GitHub → 右上角 + 号 → New repository

  • Repository name：Lynlix.github.io

  • 选择 Public

  • 点击 Create repository，然后就先不用管了

3.创建项目仓库（私有）

项目仓库：用于存放hexo项目源码、主题配置、文章图片等，仓库名称无要求，不过建议与本地Hexo项目名称一致。

  • 同样新建仓库，Repository name 例如 Lynlix-Hexo

  • 选择 Private

  • 点击 Create repository

四、GitHub Pages网站自动部署

1.生成部署专用SSH密钥

为了让 GitHub Actions 能够把生成的静态文件推送到公开仓库，我们需要一个独立的 SSH 密钥对，专门用于自动部署。

  • 在 Git Bash 中执行：ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_deploy -C "deploy-key"，一路回车不要设置密码。

  • 不出意外的话去C:\Users\用户名\.ssh目录能够找到生成的部署密钥

  • 进入部署仓库 lynlix.github.io 页面 → Settings → Deploy keys → Add deploy key

  • 部署公钥文件里的内容添加到部署仓库：

    • Title 填 GitHub-Actions-Deploy

    • Key 粘贴 id_ed25519_deploy.pub 的内容

    • 注意必须勾选 “Allow write access”，否则无法推送！

  • 进入项目仓库 Lynlix-Hexo → Settings → Secrets and variables → Actions → New repository secret

  • 部署私钥文件里的内容添加到私有仓库：

    • Name 填 HEXO_DEPLOY_KEY（名字可自定义，但后续工作流中要一致）。

    • Value 粘贴id_ed25519_deploy的内容

六、博客文章、图片部署

Hexo支持使用 Markdown 编写文章，默认格式为.md文件，所有文章统一存储于<项目根目录>/source/_posts/目录下。

但是如果需要在.md文件中插入图片的话，如何引入图片路径使其既能支持Markdown语法预览，又能完成网页图片渲染却是个问题。网络上关于这个问题有很多不同的解决方法，在此提供一种可供参考的思路：分别安装VSCode扩展与Hexo插件，平时本地使用VSCode预览、编写Markdown，网页渲染更新时则由Hexo插件自动将图片路径转换正确。

1.文章管理

  • 打开并修改项目根目录下的_config.yml配置文件

  • 在 _config.yml 中开启：

  • 开启后再执行指令hexo new "文章名"新建文章时，Hexo就会额外生成一个同名文件夹用于存储插入相应文章中的图片

  • 安装 hexo-image-link插件，用于将图片的相对路径转成正确的资源路径

  • 用VSCode打开_posts文件夹，然后在文章里随便插入一张同名文件夹下的图片并保存

  • 本地预览：在Hexo项目的根目录下，打开终端执行以下指令

  • 点击文章进去浏览，不出意外的话是会加载出图片的

2.本地编辑Markdown

VSCode本身内置预览与编辑Markdown文本的功能，只需要稍加修改VSCode粘贴图片时的默认插入路径，即可使用VSCode编辑文章。

  • 点击VSCode左下角小齿轮图标，打开设置

  • 输入 markdown.copy，找到 Markdown> Copy Files:Destination

  • 添加项：Key为 **/*.md, value为目标路径：${documentBaseName}/${fileName}

也可选择其他VSCode扩展（配置好图片插入路径即可），使其编辑Markdown文件更加方便。

3.图片引用

除了需要在Markdown文档中插入的图片外，还有一些常用于背景、封面、图标替换的其他图片，这些图片往往存储于根目录下的source/images路径下，通过相对路径/images/img.png的形式引用，Hexo会自动索引images目录下的图片并在网页中渲染出来。
